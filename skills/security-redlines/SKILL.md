# 安全红线（Security Redlines）

> 全体成员铁律，违者立即回滚 / 上抛。借鉴 mitabase-workspace 的安全红线，适配本小队；原为仓库规范，现作为可执行 skill 挂全队。
> 本 skill 是安全铁律的**完整版**；`team-canon` 的铁律为其摘要（随时生效）。

## 是什么 / 何时用

规定五条**不可越界**的安全底线。任何角色在任何操作（评论 / 提交 / 建 MR / 写文档）中都适用。

**用**：所有 MR 提交前；涉及鉴权 / 信任面 / 密钥的变更；任何可能把凭据写进文本的动作。

## 一、凭据绝不入库（最高优先级）

- **绝不在** issue 评论 / MR / 聊天 / 代码 / 日志 / 任何入库文本里写密码、token、域账号凭据、私钥——**包括测试环境**。
- 要传递凭据 = 升级给人类走带外渠道（私聊 / 密码管理器）。
- 配置文件一律走模板 + 环境变量，运行时机密不入库。

## 二、绝不编造 URL / 域名 / 编号

- 引用链接**只能用已知、真实的地址**，绝不凭空拼造域名或 URL。
- 引用 issue 优先写标识文本（如 issue UUID 或编号），拿不准就写纯文本，**绝不编造**。
- 引用不存在的编号或文件 = 打回。

## 三、失败必须 fail-closed

- 凡涉及鉴权 / 信任面 / 密钥的变更，缺依赖 / 缺配置时**默认拒绝 / 报错，不得放行**。
- 确需 fail-open 的例外，写明理由并升级人类。

## 四、Agent 绝不 merge

- 所有 MR 的合并动作由**人类**执行。TechLead 只建 MR，不点合并。
- 被要求 merge 时拒绝：「MR 合并由人类负责」。

## 五、不确定就上抛，绝不猜

- 分支 base / MR 目标分支不确定 → 停下 @人类，绝不自己推导。
- 拿不准的判定 / 范围边界 → 升级人类，不硬做。

## 完成判据（本 skill 视为已遵守）

- [ ] 全部入库文本（评论 / MR / 文档 / 代码 / 日志）**零凭据**；需传凭据已升级人类走带外；
- [ ] 引用的 URL / 域名 / 编号**全部真实可查**，无编造；
- [ ] 涉鉴权 / 信任面的变更**默认 fail-closed**，例外有理由 + 已升级；
- [ ] 未执行任何 merge；
- [ ] 不确定项（base 分支 / MR 目标 / 范围边界）已停下上抛，未自行推导。

## 反自我合理化

| 借口 | 现实 |
|---|---|
| 「测试环境无所谓」 | 测试环境凭据同样能被利用，红线不分环境 |
| 「本地跑一下先硬编码」 | 一旦入库就是泄漏，改起来更贵 |
| 「这个域名我猜是 xxx」 | 猜错即误导，宁可写纯文本标识 |
| 「先放行，回头补鉴权」 | 缺依赖时放行 = fail-open，直接违规 |
