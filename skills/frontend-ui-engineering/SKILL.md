# 前端 UI 工程（Frontend UI Engineering）

## 是什么 / 何时用

按**生产级**标准实现用户界面：可访问、响应式、视觉精致、贴合设计系统。目标是让 UI 看起来像**懂设计的工程师**做的，而不是 AI 生成的通用货。

**用**：新增 / 修改 UI 组件或页面、实现响应式布局、加交互与状态、修视觉 / 交互问题。

**不用**：纯后端逻辑改动。

## 与设计的关系

实现要对 mockup 负责：**以 mockup 与设计 Token 为基准**，不擅自改设计。发现设计有问题 → 反馈给 Product，不在实现里私自「优化」。

## 组件架构

- **就近放置**：组件实现、测试、类型、hook 放在一起。

```
src/components/
  TaskList/
    TaskList.tsx
    TaskList.test.tsx
    use-task-list.ts
    types.ts
```

- **组合优于配置**：优先可组合的子组件，而非一个满是 props 开关的巨组件。
- **组件保持聚焦**：一个组件做一件事；过长就拆。
- **状态就近**：能放组件内的状态别往全局塞；只有跨组件共享才提升。

## 设计系统对齐

- 颜色 / 间距 / 圆角 / 阴影 / 字号**一律走 Design Token / CSS 变量**，**禁止硬编码色值**。
- dark mode：所有 token 必须成对定义（亮 / 暗），逐项验证切换正确。
- 不引入「AI 审美」：不用紫色渐变、无意义装饰、过度圆角等通用套路；跟随项目既有语言。

## 全状态实现

每个交互组件都要有：默认 / hover / active / focus / disabled / loading / error / empty / success。
**空态、错误态、加载态最容易被漏**，实现时列清单逐项打勾。

## 响应式

- 桌面 / 平板 / 移动三档断点，移动优先。
- 移动端零横向溢出；输入控件字号 ≥16px（防 iOS 缩放）；触控目标足够大。

## 可访问性（必须）

- 语义化标签、正确 ARIA；键盘可达、焦点顺序合理、焦点可见。
- **色彩对比度达标**（正文 ≥4.5:1）；不靠颜色单独传达信息。
- 图片有 alt；表单有 label。
- 尊重 `prefers-reduced-motion`。

## 与性能的边界

- 列表接口分页 / 虚拟化；图片懒加载与合理尺寸；避免无界渲染。
- 性能专项仍走 `performance-optimization`（先测量再优化），本 skill 只保证不引入明显反模式。

## 反自我合理化

| 借口 | 现实 |
|---|---|
| 「能跑就行，样式后面调」 | 后面从不来，视觉债复利 |
| 「硬编码颜色快」 | 换主题 / 暗色时全崩 |
| 「可访问性以后补」 | 结构错了，补 = 重写 |
| 「AI 生成的样式应该没问题」 | 通用 AI 审美正是要避免的 |
