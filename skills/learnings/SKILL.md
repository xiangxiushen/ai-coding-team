# 经验规则库（Learnings）

> 把「评审 / 复盘里反复出现的坑」提炼成**可执行规则**，下次开工前先查，不再每个需求重踩一遍。
> **一条一行 + 带证据 commit**，按域分类。借鉴 mitabase `learnings`（原由 librarian 定期提炼）。
> 台账真源：`learnings/LEARNINGS.md`（Git）。**TechLead 兼任**维护。

## 是什么 / 何时用

把散落在评审意见、bug 复盘、返工根因里的**共性教训**沉淀成规则，让同一类问题只踩一次。

**用**：
- **沉淀**：每轮评审结论 / bug 复盘后，把「同类问题第二次出现」的教训提炼成规则；
- **使用**：S0 起草 PRD、S2 设计、S3 实现、S5 评审**开工前**先扫一眼本台账对应域，规避已知坑。

**不用**：不替代治理 skill（`review-checklist` / `security-redlines` 等），本台账是**从实战提炼的补充**。

## 台账格式

**一条一行**，格式：

```
[N] 规则文本。← <证据：仓 / commit / MR / ADR 编号>
```

- 前缀 `[域-序号]`：域见下表，序号在域内递增。
- 规则文本：**祈使句、可执行**（写「必带 X」「禁止 Y」），不写「注意 XX」。
- 证据：指向产生这条规则的 commit / MR / ADR / issue，**无证据不入库**（防臆造规则）。

## 域分类

| 域 | 前缀 | 示例 |
|---|---|---|
| 身份 / 链接 | `ID` | 归一入口唯一、失败不 fallback |
| 契约 / PRD | `CT` | 实现前先确认契约与 PRD，不自加未定义字段 |
| 后端 | `BE` | 跨域走对应域服务，写码前确认边界 |
| 前端 | `FE` | 异步（useEffect / fetch / 定时器）必带 AbortController / 清理 |
| 安全 | `SEC` | 外链抓取白名单、禁输出凭据 |
| CI/CD | `CI` | 新建流水线必配并发竞态防护 |
| 开发工作流 | `DEV` | 开工前同步主线，避免过时分支 |
| 共享组件 / 复用 | `RU` | 组件复用验收清单（多宿主 + 降级兜底） |

## 提炼流程（评审 / 复盘后）

1. **捕获**：评审发现 / bug 复盘里识别出**有普适性**的教训（非一次性的实现 bug）。
2. **去重**：扫本台账对应域，已有同类 → 更新证据，不重复入库。
3. **提炼**：写成一条**可执行规则** + 证据锚点。
4. **入库**：追加到 `learnings/LEARNINGS.md` 对应域，走 MR（治理类 → 人类确认）。
5. **回顾**：周期性（如每周）回顾分类合理性，合并 / 归档失效规则。

## 使用纪律

- S0 / S2 / S3 / S5 **开工前查一轮**对应域，命中即规避。
- 评审时若发现某规则**被违反**，直接点名该规则编号 + 证据。
- 规则过时 → 标记失效并归档，不静默删除（Git 留史）。

## 完成判据（本 skill 视为已遵守）

- [ ] 台账 `learnings/LEARNINGS.md` 存在，条目**一条一行 + 带证据**；
- [ ] 入库规则是可执行祈使句，无证据条目未入库；
- [ ] 已去重（同类不重复）；
- [ ] 关键阶段（S0/S2/S3/S5）开工前查阅过对应域。

## 边界

- 台账是**补充**，不覆盖也不替代治理 skill 的强制清单。
- 规则变更走 MR；治理类改动须人类确认。
- 与 `merge-gate-matrix` 的「产物卫生」冲突**已拍板**：本小队**保留** PRD 变更日志（产物内保留历史），台账遵循该决定。
