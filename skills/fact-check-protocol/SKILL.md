# 事实核查协议（Fact-Check Protocol）

> **幻觉与错误归因守卫，不是质量过滤器。** Reviewer 出完评审发现后，**再跑一道独立复检**，删掉 diff 能证明为假的发现。
> 借鉴 marvel `fact-check-protocol`。它**不**判断发现是否「有用 / 值得 / 该不该提」——那是评审阶段（R1–R4）的事。

## 是什么 / 何时用

评审产出发现后，用一个**默认全部保留**的怀疑视角重读发现，**只删 diff 能明文证明为假的那几条**：批评了不存在的代码、归因到错文件、编造符号、被 diff 某行直接反驳的断言。

**用**：Reviewer 完成多轴评审、汇总结论**之前**，对发现清单跑一遍。
**不用**：不因「低价值 / 我不同意 / 无法验证」而删——那些一律保留。

## 独立性（设计的一部分）

尽量在**全新子上下文**里跑：只喂 diff + 发现清单 + 每条发现的 `evidence`，**不喂产生它的推理过程**。同上下文回收会倾向自我确认，抓得住错文件、抓不住锚点漂移。无法独立时内联跑，并在报告里注明「本次事实核查非独立上下文」。

## 不对称原则（先记住）

| 错误 | 代价 |
|---|---|
| 留下一条错的发现 | 浪费评审几秒注意力 |
| 删掉一条对的发现 | **静默销毁一个真实缺陷**，无人知晓 |

**证据不足 = 保留。** 「可疑 / 我无法验证 / 低价值 / 我看现在没问题 / 换我不会提」——全部 = 保留。

## 逐步方法（按序执行，命中即停）

### Step 1 — 保护性主题否决（凌驾一切）

如果发现的**主题**属于以下任一，**保留并停止**，不评估对错。此否决高于 Ground A/B：即使你现在确信它错了，只要是保护性主题就留下。

- **内存安全**：分配大小、缓冲区长度、越界、off-by-one、use-after-free、空指针解引用
- **并发**：锁与锁模式、原子操作、数据竞争、未兑现的同步论证
- **声明 / 链接一致性**：声明与定义不符、可见性 / 修饰符不匹配、缺声明
- **行为 / 兼容性变更**：旧代码产生而新代码不再产生的消息、字段、状态、默认值、错误路径；生命周期中时序移动的计数 / 副作用
- **函数接受却从不使用的参数**

> 这些类别里，一次误删代价最大，而你自己的「确信」最不可靠——在保护性主题上你没有资格确信。

### Step 2 — 价值否决

发现讲的是风格 / 格式 / 命名 / 空行 / 注释措辞 / 可读性，**且它陈述的内容对这份 diff 为真**？→ **保留并停止**。价值高低不是本阶段的职责（它作为 `low` 留存）。

### Step 3 — Ground A：描述的代码不在其主题文件的 diff 里

发现描述的那个符号 / 语句 / 构造，在它**点名的那个文件**的 diff 里**一处不出现**（只看该文件；同构出现在兄弟文件也救不了它）。典型形态：

- 讨论函数体，而该文件只有声明或引用
- 在无宿主语言逻辑的文件（查询 / 构建 / 标记 / 配置）上讨论宿主语言逻辑
- 声称代码被删除或错误已处理，而主题文件 diff 里没有这种改动

→ **移除。**

### Step 4 — Ground B：diff 某行明文反驳其核心断言

发现断言一个具体事实，而 diff 里有一行**明文、无需推理即可读出的**相反内容（不同于 Ground A，反驳行可在该组任意文件）。典型形态：

- 说某标识符未使用，diff 显示它被使用
- 说缺某检查 / 分支 / 断言，diff 里有
- 说某值是硬编码，diff 显示它从变量读取
- 说某东西声明了两次，diff 里恰好只有一次声明

> 下结论前，在**该组每个文件**里搜发现描述的东西——不只看它引用的片段。引错了行但描述的东西 diff 里确实存在的发现是**正确的**，保留。→ 确有一行真正反驳才**移除**。

### Step 5 — 保留

其余全部。可疑、无法验证、次要、或你不同意它的修法——都保留。

## 不构成移除理由

- `evidence` 字段为空 / 单薄 / 不好用（缺纸面 ≠ 假断言）
- 讲风格 / 命名 / 可读性且**内容为真**（低价值 ≠ 不正确）
- 推理的是运行时行为 / 业务语义 / 你看不到的文件（评审有你没有的访问权限）
- 你不同意它的建议，或认为被指的代码这样写也行
- 你无法确认（不可验证 ≠ 不正确）
- 找对了真问题但引了略偏的行——评判断言，不评判引用
- 顺带说错、但核心断言成立

## 测试（判定门槛）

若你**指不出**确立 Ground A 或 Ground B 的那**具体 diff 行**，发现**保留**。需要多于一步推理才能到达矛盾 = 没有矛盾 → 保留。

## 输出

按给定 `id` 逐条给判定，**只给这一张表**（不重排、不改写描述、不改 severity、不点评整场评审）：

```
verdicts[]: { id, verdict: keep|remove, basis }
```

- **remove** → `basis` 必须引用确立 Ground A/B 的 diff 行：`path:line` + 该行文本。这是移除的全部举证责任。
- **keep** → `basis` 只写命中的步骤号（`1` 保护性主题 / `2` 价值否决 / `3`/`4` 审过未达 / `5` 默认）。
- **每个 id 都要有一行**；遗漏的 id 被调用方读作 `keep`（安全方向），但仍要求给全。

> 全 `keep` 是**正常、预期的结果**，不是你什么都没做。

## 信号提示

- **大量 Ground A 移除 = diff 命令推错了**，不是 reviewer 在幻觉。发现超过两三条像 Ground A 时，**先停下重核 diff 命令**再动手。
- 拿不到 diff / 仓库 → **只返回这个事实**，不要凭感觉「顺手评一遍」。

## 完成判据（本 skill 视为已遵守）

- [ ] 已用独立 / 内联子上下文对发现清单跑一遍，并注明是否独立；
- [ ] 每条发现都有 `keep`/`remove` 判定 + basis；
- [ ] 每条 `remove` 都引用了具体 diff 行（path:line + 文本）；
- [ ] 未因「低价值 / 无法验证 / 不同意」而移除；
- [ ] Ground A 异常偏多时已回查 diff 命令。
