# 缺陷管理（Defect Management）

> **你是开发小队的缺陷管理官**。缺陷怎么登记、怎么定级、多久修、怎么关闭、怎么度量，全部对照本 skill，**不凭印象、不拍脑袋**。
> 本 skill 是缺陷治理的**单一真源**。QA 发现缺陷时、Dev 修缺陷时、Leader 收敛门禁时，都对照本 skill。
> 借鉴 mitabase-workspace 的 `standards/defect-management.md`，适配本小队场景；现作为可执行 skill 挂给 QA。

## 是什么 / 何时用

定义缺陷从发现到关闭的**完整闭环规则**：生命周期、定级与 SLA、登记规范、关闭条件、复盘触发、度量目标。

**用**：S4 发现 AC 失败 / 边界问题；S3 自审发现回归；评审提出可复现缺陷；生产逃逸缺陷回填。

**不用**：纯需求变更（走 PRD 变更回流，见 `prd-management`）、纯评审建议（走 Reviewer 的 severity 标注）。

## 一、生命周期

```
发现 → 登记 → 定级 → 分派 → 修复 → 验证 → 关闭
 QA     QA     QA    Leader   Dev    QA     QA
```

每个缺陷**一条独立记录**（Multica issue 或 `bug-N.md`），**不合并、不沓写**。同一根因引发多个现象时，登记为一条并列出全部现象。

## 二、定级与时限（SLA）

| 级别 | 判据（满足其一即达级） | 响应时限 | 修复时限 |
|---|---|---|---|
| **P0** | 无法完成核心流程 / 数据丢失或错误持久化 / 影响 >50% 用户 / 安全漏洞 | 立即 | **4 小时** |
| **P1** | 核心功能受损但有绕行 / 影响 10%–50% 用户 / 关键边界失效 | 4 小时 | **24 小时** |
| **P2** | 次要功能异常 / 影响 <10% 用户 / 体验缺陷 | 24 小时 | **下一迭代内** |
| **P3** | 文案 / 样式 / 优化建议 / 边缘场景 | 无硬时限 | 视排期 |

> 定级**由 QA 出、Leader 复核**；有争议时上抛人类。**禁止把 P0/P1 降级处理**来保住门禁——降级必须写明理由并经人类确认。

## 三、标题与内容规范

- 标题格式：`[bug][域模块] 自然语言描述`，例：`[bug][job] 超期停用用户删除时未清理关联记录`。
- **禁止**模糊标题（如「积分问题」「删除有问题」）——标题要能让人不看正文就知道是什么。
- 正文必含：复现步骤、期望 vs 实际、影响范围、**证据**（日志 / 截图 / 命令输出 / 接口返回）、环境与版本。

## 四、关闭规则

| 关闭理由 | 谁关 | 前置条件 |
|---|---|---|
| 已修复 | QA | 修复后原复现路径验证通过 + **P0/P1 必附回归结果** |
| 无法复现 | QA | **3 次不同环境**尝试复现失败，记录尝试环境 |
| 设计如此 | 域 owner | **必须附 PRD / AC 依据**，不能口头认定 |
| 重复 | QA | 关联到已有缺陷后关闭，不静默丢弃 |

> 关闭动作**由 QA 执行**（设计如此类由域 owner 附依据、QA 执行）。Dev 不自行关闭自己修复的缺陷。

## 五、复盘触发

命中任一即触发复盘（Leader 组织，出 RCA，见 `RCA/README.md`）：

- 生产环境 P0 / P1；
- 同模块**月累计 ≥3 个**缺陷；
- **逃逸缺陷**（本该在 S3/S4 拦住却漏到生产）。

## 六、度量目标（门禁与迭代健康度）

| 指标 | 目标 |
|---|---|
| 缺陷逃逸率 | **< 5%** |
| P0 修复时长 | **< 4 小时** |
| 缺陷重开率 | **< 3%** |
| **P0/P1 回归覆盖率** | **100%** |

> 这四条与 S4 门禁一致：**P0/P1 回归覆盖 100%** 未达 → S4 门禁不放行。

## 完成判据（本 skill 视为已遵守）

- [ ] 每个缺陷都是**独立记录**，含复现步骤 + 期望 vs 实际 + 影响范围 + **证据** + 环境版本；
- [ ] 定级对照本表四档判据，无「凭感觉」定级；P0/P1 未降级（降级有理由 + 人类确认）；
- [ ] 标题符合 `[bug][域模块] 描述` 格式，不模糊；
- [ ] 关闭走本表四种理由之一，P0/P1 附回归结果，无静默关闭；
- [ ] 命中复盘触发条件时已交 Leader 走 RCA。

## 反自我合理化

| 借口 | 现实 |
|---|---|
| 「这个是偶发，不算 bug」 | 偶发只是还没定位根因，先登记再查 |
| 「用户不会碰到这个路径」 | 你无法证明；有路径就有风险 |
| 「修好了，不用回归」 | 修复引入新问题是最常见回归来源 |
| 「先记着，回头补单」 | 不登记的缺陷 = 不存在的缺陷，回头从不会来 |
| 「降个级先过门禁」 | 降级必须写理由并经人类确认，不是门禁橡皮擦 |
