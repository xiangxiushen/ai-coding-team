# PRD 管理（PRD Management）

## 是什么 / 何时用

把人类投喂的需求（Confluence 链接 / issue 描述）变成**可评审、可追溯的 PRD**，并作为小队**唯一需求真源**持续维护；任何因 bug、优化、澄清导致的需求变化，都由本 skill 回流更新 PRD。

**用**：受理新需求、起草 / 修订 PRD、需求变更追溯。
**不用**：技术设计（走 `spec-driven-development`）、mockup 产出（走 `mockup-design`）。

## 真源约定（不可动摇）

- **PRD 真源 = Git 仓库 `docs/prd/<需求id>/PRD.md`**（Markdown），变更走 MR，**人类确认为门禁**。
- **Confluence / Jira 仅作只读输入源**，不是需求真源，小队不维护其状态。
- mockup 与 PRD 同目录：`docs/prd/<需求id>/mockups/`。
- 需求 id 用 Multica issue 编号或人类给定的标识，**拿不准先问，不编造**。

## 输入 → 输出

- **输入**：人类投喂的需求（Confluence 链接 / issue 描述 / 口头说明）。
- **输出**：`PRD.md`（六段结构，见下）+ 变更日志；含 UI 时附 mockup 链接。

## PRD 六段结构

1. **背景与目标**：为什么做、解决什么问题、成功指标是什么。
2. **范围**：`In scope` / `Out of scope`（**显式写出不做什么**）。
3. **功能需求（FR）**：逐条编号（FR-1、FR-2…），每条可独立验证。
4. **验收标准（AC）**：每条 FR 对应可测 AC（AC-1.1…）；这是 Dev 实现与 QA 判定的**共同基准**。
5. **设计说明**：交互流程 + mockup 链接（页面 / 组件 / 全状态 / 响应式）；无 UI 则写明「无 UI 变更」。
6. **变更日志（Changelog）**：版本 + 日期 + 变更点 + 原因 + 触发来源 + 确认人。

## 核心流程

1. **受理**：读需求源，通读并列出**缺漏与歧义**。缺关键信息 → `blocked` 并 @人类，**不猜、不编**。
2. **起草 PRD**：按六段结构写；FR / AC 逐条编号；范围与边界显式化。
3. **设计**：需求含 UI → 调 `mockup-design` 产出 mockup，链接嵌入 PRD 设计段。
4. **提审**：PRD（+ mockup）交**人类确认**（门禁）。
5. **入库**：确认后提交 Git `docs/prd/`（分支从 `release` 切，MR 由 TechLead 建、人类 merge）。
6. **交付下游**：PRD 链接交 TechLead，进入 S1 拆解。

## 变更回流（本 skill 的核心价值）

任何阶段（S1–S6）都可能发现需求变化，判据如下：

| 变更类型 | 是否写 PRD | 处理 |
|---|---|---|
| 纯 bug 修复（实现与 PRD 一致） | **否** | 走 Dev 修 bug，不动 PRD |
| bug 暴露了 PRD 的歧义 / 遗漏 | **是** | 补写 PRD（澄清 AC 或范围） |
| 优化改变了行为 / 输出 | **是** | 更新 AC 或设计段 |
| 需求澄清 / 范围调整 | **是** | 修订 FR / AC / 范围 |

**回流流程**：发现变更 → 起草 PRD 修订 + 追加变更日志条目 → **人类确认** → 更新真源 → 触发下游以新版本重跑受影响阶段。

**变更日志规则**：
- 每版追加一条（版本 / 日期 / 变更点 / 原因 / 触发来源 / 确认人），**不删历史**。
- 变更后 PRD 版本号递增，下游（Dev / QA / Reviewer）以**最新版本**为准。
- PRD 变更**必须人类确认才生效**——未经确认的变更不驱动下游。

## 反自我合理化

| 借口 | 现实 |
|---|---|
| 「代码已经改了，PRD 回头再补」 | 不补 = 需求真源与实现漂移，下次变更无从判断「谁对」 |
| 「小的澄清不用记」 | 只有记录过的变更才可追溯；口头澄清等于没发生 |
| 「AC 写模糊点，实现灵活」 | 模糊 AC = QA 无法判定 = 必然返工 |
| 「先不写 out of scope」 | 不写边界 = 范围无限膨胀，交付无终点 |
| 「这是技术细节，PRD 不用管」 | 若技术细节改变了行为 / 对外表现，就是需求变更，必须回流 |

## 完成判据

- PRD 六段齐全；FR / AC 逐条编号且可测。
- 范围含显式 `Out of scope`。
- 含 UI 时，设计段 + mockup 链接齐全。
- 变更日志完整（每版一条，含确认人）。
- 有**人类确认记录**（谁、何时）。

## 与其他 skill 的边界

- 技术方案 / 实现细节 → 交 `spec-driven-development`（Dev）。
- mockup 视觉产出 → 交 `mockup-design`（Product 兼）。
- 设计还原度验收 → 交 `ui-design-review`（Reviewer / QA）。
- PRD 一致性的评审 → Reviewer 按 skill `review-checklist` 的「PRD 一致性轴」核对。
